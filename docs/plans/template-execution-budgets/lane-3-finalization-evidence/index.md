# Compilation/input finalization evidence

The [component report](../lane-3-finalization.md) distinguishes local component validation from combined release acceptance. All files here are fork-only evidence.

- `measurement-inputs.json`, `measurement-stages.json`, `results.json`, `matched-benchstat.log`: original/graph/input controlled samples and profiles. Six interleaved one-second samples retain separate streaming, owned, Background, live and restricted modes. Capacity screens are shorter diagnostics.
- `followup-inputs.json`, `followup-stages.json`, `follow-results.json`, `follow-pair-benchstat.log`, `follow-capacity-benchstat.log`: current graph checkpoint, scope-map reuse, input-frame and runtime-reset comparisons. `input-shape-results.json` and `input-shape-stages.json` retain the nested/shared/large-data tradeoff.
- `*-cpu-flat.log`, `*-cpu-cumulative.log`, `*-alloc.log`, `*-alloc_objects.log`, `*-heap.log`, `*-inuse_objects.log`, `*-mutex.log`, `*-block.log`: separate CPU, allocation/object, live-memory/object and contention views. Profile timings are not normal benchmark samples. RSS is in the corresponding profile/layout log.
- `*-resolved-*.log`, `follow-*-lines-*.log`, `shape-*-source.log`, `profile-source-resolution.json`: exact frozen source attribution and hash proof. An initial unresolved-source report and missing-regexp failures are retained; use the resolved reports. A missing sample is not zero cost.
- `selected-*-receipt.json`, `selected-final-inputs.json`, `selected-vet.log`: selected normal/race/vet evidence. The original finite-work diamond failure and an incorrect prototype active-version shortcut remain as failing controls, followed by passing fixed workflows.
- `variants.json`, `*.patch`: production deltas from exact base `0e277b3017b4afae1f984663c4e9244b4de0b290` for every measured variant. The test harness is retained as `.go.txt`; it extends the existing corpus rather than substituting another evaluator. `selected-source-proof.json` records the final implementation's equivalence, apart from one comment and later tests.
- `raw-profile-binary-sha256.json`: hashes of original pprof files/test binaries retained locally in `.git/finalization`. `artifact-hashes.json` covers raw/published portable artifacts. Local paths and unrelated queue notices are normalized/removed; observations are retained.

`measure-measured.py` is the exact first running harness (hash matches the recorded manifest). `followup.py` and `input_shapes.py` record later distinct batches. All execution/cleanup deadlines are recorded, and queue time is separate. The first batch's cold graph prototype predates one additional metadata-work checkpoint; the follow-up includes it. Do not relabel earlier cold results as the selected source's measurements.

Raw sources and overlays are immutable per measurement. The `-source_path` checkout root is only the root under which unique `.git/finalization/...-source/*.go` and `followup-frozen/*.go.txt` paths resolve. It does not select current production files by basename. Hash checks confirm the files used for source views match the corresponding build overlays.

For reproduction on the un-packaged Go 1.16-floor module, use an alternate Git index at the base, apply the chosen variant patch to that index and materialize its Go blobs into an artifact directory. Overlay those files onto the checkout, add `benchmark.go.txt`, `candidate-modes.go.txt` and `strategy_benchmark.go.txt` as Go test inputs, and run the recorded command under installed host-gate. No new branch/checkout, source mutation, fuzzing, or quota change is needed. Module/dependency/corpus hashes must match the manifest. Final packaging changes require a deliberately adapted harness/module baseline.

Serial profiles do not certify concurrent scalability or a heap/RSS cap. The final combined min/current-Go CI, full modes/fixtures, p50/p99, concurrent contention, cancellation overshoot and external module resolution remain mandatory Lane 4 gates.
